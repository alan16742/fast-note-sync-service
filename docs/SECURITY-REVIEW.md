# 安全实现检查与修正

本次检查覆盖数据库敏感字段加密及迁移、密码哈希、登录与分享令牌、Webhook 凭证的保存/回显/测试/发送流程，以及前端请求头编辑。

## 保留的实现

- 数据库敏感字段使用 AES-256-GCM；每次写入生成随机 nonce，解密校验认证标签，运行时拒绝非空明文及错误密钥。
- 数据迁移按物理数据库在事务中转换敏感值并记录版本；数据库访问层加解密不修改调用方原始对象。
- 新密码使用 Argon2id，已有 bcrypt 哈希仍可验证，避免升级锁定已有账户。
- 通知 HTTP 客户端禁止重定向，并在建立连接时解析、检查和连接同一个 IP，限制超时与响应大小。

## 本次修正

- 移除公开的数据库示例密钥作为可运行默认值；拒绝空密钥、短于 32 字节的密钥和原公开示例密钥。自动初始化使用 crypto/rand 生成 256 位随机密钥，随机源失败直接报错，新建配置文件权限为 0600。长度检查不能替代随机性，手动配置也应使用随机生成的密钥。
- 删除没有调用方的 MD5/XOR/旧流加密工具 `pkg/util/crypto.go`。
- 删除分享令牌的 AES-ECB 旧格式兼容分支，该分支只有 24 位校验码；保留 HMAC-SHA256 格式。JWT 解析限定 HS256 并要求过期时间。
- 密码哈希解析拒绝重复/非法参数和过长编码，并限制单次验证参数上限为 256 MiB、6 次迭代。当前生成参数仍为 64 MiB、3 次迭代。
- Webhook 保存与测试发送共用请求准备方法；在规范化之前拒绝非法名称、重复名称和控制字符，防止空白清理掩盖非法输入。
- 目标协议、主机/端口或路径改变时，禁止自动复用空白敏感请求头，必须重新填写或移除相应行。
- API 新增 `protectedHeaders`：仅返回有已保存敏感值的请求头名称，值仍为空。前端据此展示“已配置密钥”和“留空保留”，不使用伪造的星号作为实际值。
- 前端使用逐行名称/值输入，敏感值使用密码框；删除行意味着删除请求头，普通空值仍是普通空值。保存与测试复用相同的行校验和序列化逻辑。

## 升级影响与边界

- 旧 AES-ECB 分享链接将失效，需要重新生成；现用 HMAC 分享链接保持可用。缺少过期时间或使用非 HS256 签名的登录 JWT 将被拒绝。
- 已有数据库必须继续使用原加密密钥。若已有密文使用弱密钥，应先在隔离副本上完成旧密钥解密、新密钥重加密及恢复验证，再切换配置；不能仅替换配置中的密钥。本次没有操作线上数据，也没有提供自动密钥轮换。
- 密钥应与数据库备份分开保存；数据库字段加密不会消除既有备份、SQLite 空闲页或历史日志里可能存在的旧明文，也不替代 HTTPS。
- Webhook 敏感请求头和 URL 查询参数依旧按名称识别；普通请求头可回显，任意自定义名称或 URL 路径中的凭证不会自动被识别为敏感值。数据库 URL 整体加密，但这不等于 API 隐藏整个 URL。
- 本次没有改动存储/备份功能原有的凭证读取语义，数据库加密与 API 是否允许账户所有者读取凭证是不同的边界。
