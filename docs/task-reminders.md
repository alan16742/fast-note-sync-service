# 待办提醒与通知渠道

在 WebGUI 的「通知渠道」中配置 Server酱³ / Turbo、Bark 或自定义 Webhook；渠道只保存凭据、传输方式和消息模板。在「自动化」中新增 `todo_reminder` 事件分支，选择笔记库、公共时区，以及一个或多个通知渠道。正文匹配由 `note_content` 分支负责，待办分支只负责专用待办解析。

- Server酱³：填写 App 对应的 SendKey；系统从 `sctp<uid>t...` 提取 UID，发送到 `https://<uid>.push.ft07.com/send/<sendkey>.send`。已有 Turbo 的 `SCT...` Key 仍使用 Turbo 接口，两种 Key 不通用。
- Bark：设备 Key 与服务基础地址分开填写。地址留空使用 `https://api.day.app`，通过 `/push` JSON 接口发送，设备 Key 放在请求体。自建服务应提供公网可访问的 HTTP(S) 地址；发送器会拒绝私网、回环地址和重定向。
- `todo_reminder` 分支使用规则公共 IANA 时区，默认 `Asia/Shanghai`；任务文本中的 `tz` 仍按待办解析器的既有语义处理。
- 路径前缀、Glob 和正文关键词等条件都属于触发器，不属于通知渠道。渠道只负责把已经匹配的事件发送出去。
- 通知渠道可自定义标题和正文模板；保存后可在 WebGUI 的渠道列表中点击「测试发送」发送一条合成消息，不会读取或修改笔记。

```markdown
- [ ] 买菜 @(2026-09-06 22:45; remind=-1h,0,+1h)
* [ ] 检查服务器 @(2026-09-06 09:00; remind=0; tz=Asia/Shanghai)
- [ ] 发布版本 @(2026-09-06 22:45; remind=0)
```

只识别 Markdown 任务列表。代码块、引用以及行内代码里的示例不会产生提醒。勾选 `[x]` / `[X]`、删除任务或删除笔记都会停止未来投递，已发送消息保持不变。

## 元数据语义

时间写在 `@(...)` 中，日期必须是第一个值；后续字段使用分号分隔。推荐书写顺序：`时间; remind; until; tz`。解析后使用结构化时间与秒数计算，不再用原始 Markdown 字符串判断提醒时间。

日期、提醒参数和时区必须属于同一个 `@(...)` 块。

| 字段 | 规则 |
| --- | --- |
| 日期 | 必填，写作 `@(YYYY-MM-DD HH:mm; ...)`，按任务或 `todo` 触发器的时区解释 |
| `remind` | 缺省为 `0`；支持 `d/h/m`，负号提前、正号延后；转换为秒后排序去重 |
| `until` | 绝对截止时间，包含截止时刻；到最后一个正偏移后，以该偏移为间隔继续催办。没有正偏移时不追加提醒 |
| `tz` | IANA 时区，如 `Asia/Shanghai`、`America/New_York` |

例如 `@(2026-09-06 22:45; remind=-1h,0,+1h,+2h; until=...)`，显式提醒后继续按最后偏移间隔发送，直至 `until`。

单项偏移最多 366 天，每个任务最多 128 项偏移。非法日期、时区、字段、重复字段或超限值会记录诊断并跳过该任务，同一笔记中的有效任务继续处理。

## 消息模板

标题和正文支持 `{{content}}`、`{{vault}}`、`{{path}}`、`{{old_path}}`、`{{action}}`、`{{title}}`、`{{due}}`、`{{timezone}}` 和 `{{url}}`。笔记变更通知主要使用前五项；待办提醒还会提供任务标题、到期时间和笔记链接。当前通知不适用的变量替换为空，未知变量原样保留。

模板在服务端渲染后再发送，正文仍受通知渠道的长度限制；模板不会执行 Markdown、HTML 或脚本。

## 运行与恢复

- 后台每 10 秒检查变更笔记和到期任务，网络投递不阻塞笔记同步。
- 每个任务和触发器只维护下一条待投递记录，保存在用户的 `reminder_job` 表；SQLite 按既有路由使用独立用户数据库文件。
- 创建 `todo_reminder` 事件分支时，从触发器创建时间与笔记服务器更新时间中较晚的时刻开始排程，不补发早于启用的历史提醒。
- 重启后恢复进度；每个任务最多补发一条待处理提醒，然后从当前时间继续，避免积压消息集中轰炸。已超过 `until` 的提醒不再投递。
- 每次发送前重新读取渠道、笔记和笔记库状态，确认任务仍未完成且仍匹配。
- 失败从 30 秒开始指数退避，最长 1 小时；每次请求默认超时 10 秒。HTTP 状态与平台业务状态均验证。
- 数据库租约避免正常并发重复发送。HTTP 推送与本地数据库无法组成同一事务：如果远端已接收，但进程在确认保存前崩溃，重试仍可能产生重复消息。

Bark 提醒按笔记库分组，点击可通过 Obsidian URL 打开笔记。
